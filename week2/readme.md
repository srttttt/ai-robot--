# 本次操作过程叙述（活动说明）

本次实验主要围绕 ROS 基础通信机制、TurtleSim 仿真控制以及 GitHub 版本管理展开，通过实际操作进一步理解了 ROS 系统中节点通信、话题发布以及机器人运动控制的基本原理，同时熟悉了 Git 在机器人项目开发中的使用流程。本次实验不仅完成了代码同步与仿真测试，还观察了机器人在仿真环境中的边界碰撞现象，加深了对机器人控制逻辑和仿真约束机制的认识。

首先，在 Git 版本控制部分，完成了本地代码提交与远程仓库同步操作。实验过程中在 Ubuntu 终端中依次执行了：

```bash id="j4x7qb"
git add .
git commit -m "Update ROS turtlesim experiment"
git push
```

其中：

* `git add .` 用于将当前目录下所有修改文件添加到暂存区；
* `git commit -m` 用于生成本地提交记录；
* `git push` 用于将本地代码同步到 GitHub 远程仓库。



通过本次 Git 操作，进一步熟悉了软件开发中的版本管理流程。在机器人项目开发中，Git 能够帮助开发者记录实验过程、保存代码历史以及管理不同阶段的实验结果。由于 ROS 项目通常会涉及大量节点文件、Launch 文件、模型资源以及参数配置，因此使用 Git 能够有效提高项目管理效率，同时也方便后续多人协作开发。

完成 Git 操作后，开始进行 ROS TurtleSim 仿真实验。首先启动了 `turtlesim` 节点，成功打开了 TurtleSim 图形界面。在窗口中可以看到一只绿色的小海龟以及运动轨迹背景。TurtleSim 是 ROS 中经典的教学工具，通过简单的二维仿真环境，可以帮助学习者快速理解 ROS 的通信机制和机器人控制方式。相比复杂的三维机器人仿真环境，TurtleSim 更加轻量化，适合初学者学习 ROS 的基础结构与消息传递机制。

随后，在另一个终端中编写并运行 ROS Publisher 节点，通过向 `/cmd_vel` 话题持续发布 `geometry_msgs.msg.Twist` 类型消息，实现对海龟运动的控制。在 ROS 中，`/cmd_vel` 是一个常见的速度控制话题，很多移动机器人都会通过该话题接收运动指令。Twist 消息中包含线速度与角速度两个重要部分，通过修改这些参数，可以实现机器人前进、后退、旋转等动作控制。

本次实验中设置的速度参数如下：

```python id="a8m2vn"
linear.x = 1.0
angular.z = 0.0
```

其中：

* `linear.x = 1.0` 表示机器人沿 X 轴正方向以 1m/s 的速度前进；
* `angular.z = 0.0` 表示机器人不进行旋转。

由于角速度为 0，因此海龟始终保持直线运动状态，没有发生转向行为。

在节点运行过程中，可以在终端中持续看到 Twist 消息被发布，说明 ROS Topic 通信正常工作。同时，在 TurtleSim 图形窗口中能够观察到海龟不断向前移动，并留下运动轨迹。这一过程验证了：

* ROS 节点正常运行；
* Publisher 成功发布消息；
* Topic 通信建立成功；
* TurtleSim 能够正确接收控制指令；
* 仿真系统能够根据消息实时更新机器人状态。

在实验过程中，还通过 `ros2 topic list`、`ros2 node list` 等命令查看当前系统中的节点与话题情况，从而进一步理解 ROS 的分布式结构。ROS 的核心思想是“节点之间通过 Topic 完成通信”，不同节点之间相互独立，但可以通过消息机制协同工作。这种架构能够降低系统耦合度，使机器人系统更加模块化。

随着程序持续发送前进指令，海龟最终移动到了仿真环境边界。当海龟碰撞到边界时，终端中开始大量出现如下警告信息：

```text id="n5v8pc"
[WARN] ... [turtlesim]: Oh no! I hit the wall!
```

该现象说明 TurtleSim 内部具有边界碰撞检测机制。当机器人运动到窗口边缘时，系统会自动限制其继续向外移动，并输出警告日志。这种机制与真实机器人系统中的碰撞检测和安全限制具有一定相似性。在真实机器人系统中，如果机器人没有避障逻辑，持续向障碍物运动可能会导致硬件损坏，因此边界检测与安全保护机制十分重要。

通过观察该现象，可以进一步理解机器人控制程序中的环境约束问题。如果机器人控制逻辑只持续发送速度指令，而不进行环境感知或避障判断，那么机器人可能会不断撞击障碍物。因此，在实际机器人系统中，还需要结合：

* 激光雷达；
* 摄像头视觉；
* 深度学习目标检测；
* SLAM 建图；
* 路径规划算法；
* 障碍物检测模块；

等技术实现更加智能的运动控制。

此外，本次实验还学习了 ROS 中多个核心概念，包括：

* Node（节点）；
* Topic（话题）；
* Publisher（发布者）；
* Subscriber（订阅者）；
* Twist 消息；
* 速度控制机制；
* 仿真节点运行；
* 终端日志输出。

ROS 的核心思想是“分布式节点通信”。不同功能模块通过 Topic 相互传递消息，从而实现机器人感知、决策与控制之间的协同工作。TurtleSim 虽然只是简单二维仿真，但很好地展示了 ROS 通信架构的基本原理。

在实验过程中，还学习了如何同时使用多个终端窗口分别运行：

* turtlesim_node；
* Publisher 控制节点；
* Topic 监控；
* 系统日志输出。

这种多终端协同运行方式是 ROS 开发中的常见工作模式，也是后续学习复杂机器人系统的重要基础。通过同时观察多个终端中的输出信息，可以更方便地分析系统运行状态与调试程序问题。

通过本次实验，不仅掌握了 GitHub 代码同步流程，也成功完成了 ROS Topic 通信与 TurtleSim 控制实验。实验结果表明，ROS 节点能够正常通信，海龟能够根据 Twist 消息进行运动，同时仿真环境中的边界约束机制也能够正确触发警告信息。

总体来看，本次实验帮助进一步理解了 ROS 的基础结构与机器人运动控制原理，为后续学习 ROS2、Gazebo 仿真、SLAM 建图、MoveIt 机械臂控制以及强化学习机器人训练打下了良好基础。同时，也提高了 Linux 终端操作能力以及 Git 项目管理能力，对于今后的机器人开发实验具有重要意义。
